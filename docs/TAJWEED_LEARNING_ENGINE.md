# محرك تعلم التجويد والمراجعة المتباعدة

## الغرض والفصل العلمي

`tajweed-learning.js` محرك جدولة محلي عام، وليس مصدرًا لأحكام التجويد. لا يحمل نص قاعدة أو مثالًا أو لونًا، بل يستقبل بطاقات من طبقة بيانات مستقلة. هوية كل بطاقة تتكون وجوبًا من:

- `riwayah` — الرواية.
- `tariq` — الطريق.
- `wajh` — الوجه.
- `edition` — الطبعة/الإصدار الموثق.
- `id` — الحكم داخل هذا النطاق.

لا تدخل بطاقة ناقصة النطاق إلى الطابور. ولا تشترك بطاقتان لهما الاسم نفسه في التقدم إذا اختلفت الرواية أو الطريق أو الوجه أو الطبعة.

## الحالة العلمية الحالية

الكتالوج `tajweed-learning-catalog.json` يحوي مسودة حفص فقط، مستخرجة من شروح المشروع لرموز لقطة AlQuran Cloud `quran-tajweed`، مع أمثلة موسومة من النص المحلي. تسجل المسودة صراحة:

- `status: PENDING_SCHOLARLY_REVIEW`
- `publishableAsApproved: false`
- `tariq: source-unspecified`

لذلك تعرض الواجهة تحذيرًا واضحًا ولا تصفها بأنها اعتماد علمي. ورش وقالون والدوري مسجلة في `unavailable` ولا تنشأ لها بطاقات. عند اختيار إحداها لا يعيد سراج استخدام قواعد حفص ولا يعرض قائمة عامة بديلة.

تحقق البوابتان:

```bash
python3 scripts/verify_tajweed_learning.py
python3 scripts/verify_tajweed_scopes.py
```

تثبت الأولى تطابق القواعد الـ17 مع `mushaf_app/data/tajweed.json`، ووجود مثال موسوم لكل رمز في `quran-tajweed.json`، واكتمال نطاق حفص، وفشل الروايات غير المتاحة بصورة مغلقة. وتثبت الثانية تغطية كل خيارات المصحف، وبصمات النصوص والكتالوج، ومنع fallback بين النطاقات، وعدم فتح أي حزمة لم تجتز عقد المصدر والمراجعة.

## سجل النطاقات وعقد الحزم

يفصل `tajweed-scope-registry.json` بين مجموعات حفص وورش وقالون والدوري، ويسمح بمصفوفة `curricula` داخل كل رواية حتى لا يضطر طريقان أو وجهان أو طبعتان إلى مشاركة الحزمة. لكل مؤشر حزمة نطاق كامل وبصمة وحالة نشر. لا تكفي مطابقة اسم الرواية وحده.

يحدد `tajweed-curriculum.schema.json` عقد أي حزمة مستقلة مستقبلية:

- ربط نص ثابت باسم الملف ومجموعة البيانات وبصمة SHA-256.
- مصادر مؤرخة ذات روابط وبصمات ودليل ترخيص.
- أحكام تفصيلية وألوان ومراجع مصدر لكل حكم.
- علامات منفصلة عن النص على هيئة مقاطع Unicode code points نصف مفتوحة.
- مراجع مصدر لكل علامة، ومنع الإشارة إلى حكم أو آية غير موجودة.
- عند `APPROVED`: مراجع مؤهل، وبصمة المادة التي راجعها، ودليل، واعتماد نشر من شخص ثانٍ مختلف.

يبقى مجلد `tajweed-curricula/` بلا ملفات JSON إلى أن تصل حزمة حقيقية تستوفي ذلك. وجود نص ورش أو قالون أو الدوري في `quran-riwayat.json` لا يثبت تلقائيًا أحكام التجويد أو الطريق أو الوجه.

### مرشح ورش المحجور

فُحصت تقنيًا حزمة مولدة لورش من طريق الأزرق دون إدخالها إلى runtime: 604 صفحات، و6,214 آية فريدة، و46 معرف حكم، ولا أخطاء داخلية في البصمات أو حدود المقاطع. لكنها بقيت `QUARANTINED_NOT_PUBLISHABLE` لأن مصدر corpus الأصلي لا يسجل رابطًا أو ترخيص إعادة توزيع، ولأن 250 آية ما زالت مختلفة عن نص سراج بعد إزالة فروق التخطيط، ولغياب المراجعة المؤهلة واعتماد النشر الثاني. التفاصيل في `docs/TAJWEED_SOURCE_INTAKE.md` والتقرير metadata-only داخل `audit/tajweed-candidates/`.

لا يغير نجاح الفحص التقني حالة سجل ورش؛ تظل `curricula: []` ولا تعرض الواجهة هذه العلامات.

## خوارزمية المراجعة

لكل بطاقة سجل محلي مستقل:

- موعد الاستحقاق `dueAt`.
- الفاصل بالأيام `intervalDays`.
- معامل السهولة `ease` بين 1.3 و3.0.
- عدد التكرارات الناجحة والتعثرات.
- إجمالي الإجابات والصحيحة.
- حالة التعليق والبطاقة المتعثرة `leech`.

التقييمات:

| التقييم | الأثر الأساسي |
|---|---|
| `again` | إعادة بعد 10 دقائق، تصفير تسلسل النجاح، وخفض السهولة؛ التعثر الثامن يعلّم البطاقة `leech` |
| `hard` | فاصل بطيء (نحو 1.2×) وخفض السهولة |
| `good` | 1 يوم، ثم 3 أيام، ثم الفاصل السابق × السهولة |
| `easy` | يبدأ من 4 أيام، ويرفع السهولة ويوسع الفاصل |

الفاصل الأقصى سنة واحدة. العمليات حتمية ولا تستخدم عشوائية أو خادمًا.

## تكوين الطابور

1. تُرشح البطاقات المطابقة تمامًا للنطاق الحالي.
2. تُستبعد البطاقات المعلقة وغير المستحقة.
3. تأتي المراجعات المستحقة أولًا، من الأقدم إلى الأحدث.
4. تضاف البطاقات الجديدة حسب ترتيب المنهج.
5. الحد الافتراضي 20 مراجعة و5 بطاقات جديدة في اليوم، ويمكن ضبطه ضمن حدود آمنة.

لا يؤدي تغيير المصحف إلى حذف التقدم؛ لكنه يبدل إلى سجل نطاق آخر. زر المسح يحذف تقدم الطبعة الحالية فقط.

## واجهة التعلم

تعرض شاشة التجويد:

- النطاق الحالي وحالة المراجعة العلمية.
- المستحق، وقيد التعلم، والراسخ، ودقة الاستدعاء.
- سؤال استدعاء ومثالًا موسومًا ومرجعه.
- كشف الشرح ثم تقييمًا ذاتيًا: أعدها، صعب، جيد، سهل.

بعد كل إجابة يسجل محرك السياق حدث `TAJWEED_ANSWER` دون نص حر. وعند إكمال الطابور يسجل `COMPLETE_TAJWEED_LESSON`، فيمنع تكرار اقتراح الجلسة في اليوم نفسه.

## الخصوصية والتخزين

يحفظ التقدم تحت `quran:tajweed-learning` في تخزين التطبيق المحلي. اللقطة لا تحتوي نصوص الآيات أو الأسئلة؛ تخزن مفاتيح البطاقات والنواتج الرقمية فقط. لا يوجد اتصال شبكة داخل المحرك.

## الاختبارات

```bash
npm run test:smart
```

تغطي الاختبارات عزل الروايات والطرق، ترتيب الطابور، الحدود اليومية، التقييمات الأربعة، التعثر، التعليق، الإحصاءات، تطبيع الحالة الفاسدة، استقلال اللقطة، إعادة ضبط نطاق واحد، والحتمية.

## بوابة إضافة رواية أو طريق

لا تضاف طبقة جديدة إلى `curricula` إلا بعد:

1. تثبيت مصدر ونسخة وبصمة وحقوق استخدام، وحفظ دليل الترخيص.
2. تحديد الرواية والطريق والوجه والطبعة دون قيم عامة مضللة.
3. توفير أحكام وأمثلة وعلامات مستقلة، لا فروقًا جزئية عن حفص فقط.
4. إنشاء ملف يطابق schema وربطه بمؤشر مطابق تمامًا في سجل النطاقات.
5. تحقق آلي من المقاطع والمراجع والبصمات وعدم اختلاط النطاقات.
6. مراجعة بشرية مؤهلة لمحتوى ذي بصمة ثابتة، ثم اعتماد نشر من شخص ثانٍ.
7. تغيير الحالة إلى `APPROVED` فقط بعد حفظ دليل الاعتماد وتشغيل الاختبارات كاملة.

التعليمات التفصيلية في `tajweed-curricula/README.md`. حتى استيفاء ذلك تبقى الرواية محجوبة في السجل وفي `unavailable`، ولا يحول التطبيق غياب البيانات إلى استنتاج آلي منشور.
